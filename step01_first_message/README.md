# ☕ OrdeFflow — Шаг 1: Первое сообщение

> Мини-проект: симуляция кафе, в котором кассир принимает заказы,
> а бариста их забирает и готовит. Всё через очередь RabbitMQ.

---

## 🎯 Что мы смоделировали

Представь обычное кафе:

```
👩‍💼 Кассир                🗃️ Стойка заказов             👨‍🍳 Бариста
(send_order.py)    →→→    (очередь "orders")    →→→    (worker.py)

"Капучино, пожалуйста!"   [заказ лежит и ждёт]    "Готовлю! Письмо клиенту отправлено"
```

- **Кассир** (`send_order.py`) — принимает заказ и кладёт его на стойку  
- **Стойка** (очередь `orders` в RabbitMQ) — хранит заказы, пока бариста занят  
- **Бариста** (`worker.py`) — забирает заказ со стойки и «отправляет письмо» клиенту

Кассир и бариста **не знают друг о друге** — они общаются только через стойку.

## 🔑 Ключевые понятия

### Очередь (Queue)
Это **почтовый ящик** внутри RabbitMQ. Сообщения попадают туда и лежат до тех пор,
пока кто-нибудь их не заберёт.

```
┌─────────────────────────────────────────┐
│            Очередь "orders"             │
│  [заказ #3] [заказ #4] [заказ #5] →→→  │  ← новые добавляются справа
└─────────────────────────────────────────┘
         ↑                        ↑
   сюда кладёт               отсюда забирает
   send_order.py              worker.py
```

### Producer (Издатель / Кассир)
Скрипт, который **создаёт** сообщение и **кладёт** его в очередь.
В нашем случае — `send_order.py`.

### Consumer / Worker (Потребитель / Бариста)
Скрипт, который **слушает** очередь и **забирает** сообщения по мере поступления.
В нашем случае — `worker.py`.

## 🔍 Что происходит в коде

### send_order.py — кассир шаг за шагом

```
1. Открыть соединение с RabbitMQ (одно TCP-подключение на программу)
        ↓
2. Открыть канал внутри соединения (через него идут команды)
        ↓
3. Объявить очередь "orders" (создать, если не существует)
        ↓
4. Упаковать заказ: dict → JSON → bytes (RabbitMQ работает только с байтами)
        ↓
5. Положить сообщение в очередь через default_exchange
        ↓
6. Вывести "Заказ #N отправлен"
```

### worker.py — бариста шаг за шагом

```
1. Открыть соединение и канал (то же самое)
        ↓
2. Объявить ту же очередь "orders"
   (на случай если worker запустился раньше кассира)
        ↓
3. Подписаться на очередь через queue.iterator()
        ↓
4. Бесконечный цикл: ждать новых сообщений ↩
        ↓
5. Получить сообщение: bytes → JSON → dict
        ↓
6. Вывести "Письмо отправлено на email: заказ #N, товары: ..."
```

## 🚀 Быстрый старт

### 1. Запустить RabbitMQ

```bash
docker compose up -d
```

Подождать 10–20 секунд, проверить:

```bash
docker ps   # → контейнер "rabbit" со статусом "Up"
```

### 2. Установить зависимости

```bash
cd step01_first_message
python3 -m venv .venv
source .venv/bin/activate          # Linux / macOS
# .venv\Scripts\Activate.ps1      # Windows PowerShell

pip install -r ../requirements.txt
```

### 3. Запустить кассира

```bash
python3 send_order.py 1
# → Заказ #1 отправлен
```

### 4. Запустить бариста

```bash
python3 worker.py
# → Жду заказы. Ctrl+C для выхода
# → Письмо отправлено на anna@example.com: заказ #1, товары: Кофе в зёрнах, Фильтры V60
```

## 🧪 Эксперименты

### 🔬 Опыт 1 — Накопить заказы, потом запустить бариста

Это самый наглядный эксперимент. Убедись, что `worker.py` **не запущен**.

```bash
python3 send_order.py 3
python3 send_order.py 4
python3 send_order.py 5
```

Открой веб-интерфейс → **[http://localhost:15672](http://localhost:15672)**  
Логин: `guest` / Пароль: `guest`  
Перейди: **Queues and Streams** → очередь `orders`

Увидишь:

```
┌──────────────────────────────────────────────┐
│  orders │ Ready: 3 │ Unacked: 0 │ Total: 3   │
└──────────────────────────────────────────────┘
         ↑
   три заказа лежат и ждут бариста
```

Теперь запусти бариста:

```bash
python3 worker.py
```

Наблюдай — он заберёт все три мгновенно, **Ready** станет 0.

---

### 🔬 Опыт 2 — Бариста работает, заказ приходит сразу

Запусти `worker.py` в одном терминале. В другом терминале:

```bash
python3 send_order.py 6
```

Письмо появится в первом терминале моментально — очередь выступает как живой
канал связи, а не только как хранилище.

---

### 🔬 Опыт 3 — Заглянуть в сообщение через браузер

Останови бариста (`Ctrl+C`), отправь заказ:

```bash
python3 send_order.py 7
```

В веб-интерфейсе: **Queues and Streams** → `orders` → прокрути вниз →
раздел **Get messages** → нажми **Get Message(s)**.

Режим `Nack message requeue true` — **не меняй**: с этим флагом сообщение
вернётся обратно в очередь после просмотра.

Увидишь тело сообщения в JSON:

```json
{
  "order_id": 7,
  "email": "anna@example.com",
  "items": ["Кофе в зёрнах", "Фильтры V60"]
}
```

## 🛡️ Почему заказы не теряются

Ключевой момент шага: заказы **переживают** выключение бариста.

```
Бариста упал / выключен
         ↓
Заказы продолжают накапливаться в очереди
         ↓
Бариста снова запустился
         ↓
Забирает ВСЕ накопившиеся заказы по порядку
```

Попробуй сам:

```bash
# 1. Убедись что worker.py НЕ запущен
# 2. Отправь заказы
python3 send_order.py 8
python3 send_order.py 9
python3 send_order.py 10
# 3. Запусти бариста — получит все три
python3 worker.py
```

> ⚠️ **Исключение:** `docker compose down` удаляет контейнер **вместе с очередями**.
> После `down` + `up -d` очередь пустая. Как сохранять заказы между перезапусками
> Docker — тема следующих шагов.

## 💡 Что мы поняли на этом шаге

| Вопрос | Ответ |
|--------|-------|
| Кто такой Producer? | Тот, кто **кладёт** сообщение в очередь (`send_order.py`) |
| Кто такой Consumer/Worker? | Тот, кто **забирает** сообщение (`worker.py`) |
| Знают ли они друг о друге? | **Нет** — только о существовании очереди |
| Что если Worker выключен? | Сообщения **копятся** в очереди и ждут |
| Почему байты, а не строки? | RabbitMQ — протокол AMQP, работает с **байтами**. Сериализацию делаем сами |
| Зачем `durable=True`? | RabbitMQ 4 запретил временные очереди — это требование версии |
